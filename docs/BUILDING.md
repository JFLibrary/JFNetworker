# Bauen und testen

*Entwicklerdoku von JFNetworker auf Deutsch; die Übersicht auf Englisch steht in der [README](../README.md). Teile: [Überblick](OVERVIEW.md) · [Bedienung](USAGE.md) · [Bauen und testen](BUILDING.md) · [Aufbau](REFERENCE.md) · [Performance](PERFORMANCE.md) · [Fahrplan](ROADMAP.md) · [Marken](TRADEMARKS.md)*


JFNetworker hat eine eigene Repo, seit es am 2026-11-09 aus JFLib ausgezogen ist. Zum Bauen braucht es Rust über
rustup (1.98 oder neuer), das Werkzeug `cargo jflib` (`cargo install cargo-jflib`) für die Testskripte und
Python 3.11 für die Skripte in `tools/`. JFLib kommt von crates.io, JFScript aus seiner Repo
([JFLibrary/JFScript](https://github.com/JFLibrary/JFScript), Git-Abhängigkeit).

**Bis zum nächsten JFLib-Release** liegt ein JFLib-Checkout neben dieser Repo (`../JFLib`): Der Style `netlab`
ist noch nicht auf crates.io, darum nimmt `.cargo/config.toml` ihn und jede andere JFLib-Crate von dort
(`[patch.crates-io]`, geschrieben von `tools/jflib_patch.py`). Sobald `jflib-style-netlab` veröffentlicht ist,
fällt die Tabelle weg. Werkzeuge der Bibliothek (`i18n_check.py`, `vsym.py`, `vicon.py`) kommen ebenfalls aus
diesem Checkout.

Unter Linux immer mit `--target x86_64-unknown-linux-gnu` bauen (die Schalter in `.cargo/config.toml` erreichen
dann nur die Programme): `cargo build --workspace --target x86_64-unknown-linux-gnu`.

```
git clone https://github.com/JFLibrary/JFLib ../JFLib            # bis netlab auf crates.io liegt
cargo build --workspace                                     # target/debug/JFNetworker.exe und jfn-sim.exe
target/debug/JFNetworker.exe                                   # der Editor
target/debug/JFNetworker.exe --open tests/fixtures/campus.jfnet
target/debug/JFNetworker.exe --lang en                         # auf Englisch
target/debug/JFNetworker.exe --script tests/start_page.uis --start-page  # Skripte sehen die Startseite nur so
target/debug/JFNetworker.exe --selftest                        # Prüfungen von Modell, Simulator, Oberfläche
target/debug/JFNetworker.exe --selftest --pcap-out DIR         # dazu die Mitschnitte der Prüfungen
target/debug/JFNetworker.exe --script tests/place.uis --verify-dirty
target/debug/JFNetworker.exe --gen-topology 500 --traffic 300  # synthetischer Campus, 300 Pings (Leistung)

target/debug/jfn-sim.exe run tests/fixtures/lan_router.jfnet --scenario tests/scen/lan_router.scn
target/debug/jfn-sim.exe run tests/fixtures/lab_shards.jfnet --scenario tests/scen/lab_metrics.scn --series build/lab.csv
target/debug/jfn-sim.exe check tests/fixtures/lan_router.jfnet
target/debug/jfn-sim.exe course academy/beispiel   # ein Kurs: seine Datei, Lektionen, Bilder, Links, Labore
target/debug/JFNetworker.exe --academy-dir academy # die Kurse aus diesem Ordner statt aus data://academy
python tools/academy_index.py                                    # die Kursliste academy/index.json aus den Ordnern (--check: ist sie aktuell?)
target/debug/jfn-sim.exe course-list academy       # was eine Quelle anbietet (ein Ordner oder eine Adresse)
target/debug/jfn-sim.exe course-install academy beispiel --into build/kurse   # ein Kurs in einen Ordner, den es schon gibt
python tools/academy_e2e.py                                      # Installieren über echtes HTTP gegen einen Server auf diesem Rechner
target/debug/jfn-sim.exe decode "ff ff ff ff ff ff 02 4a 00 00 01 01 08 06 ..."
target/debug/jfn-sim.exe gen 500 --out build/campus.jfnet
target/debug/jfn-sim.exe catalog --out build/catalog.json   # Modelle und Kabelarten als JSON (für die Docs der Website)
target/debug/jfn-sim.exe rewind tests/fixtures/lab_window.jfnet 60   # Keyframes und Zeit zum Zurückspulen
target/debug/JFNetworker.exe tests/fixtures/two_pcs.jfnet --scenario tests/scen/two_pcs.scn
python tools/i18n.py                                        # jeder Text hat sein Englisch (JFLibs i18n_check aus ../JFLib)
cargo jflib test                                            # alle Skripte in tests/ (Windows)
python tools/linux_test.py                                  # dieselben unter Linux, von Windows über WSL
```

`cargo jflib test` führt alle Skripte in `tests/` aus, die Fensterskripte mit
`--verify-dirty` (Teil- und Vollbild pixelgleich); die meisten nehmen Bilder hell, dunkel und
mit 150 % nach `build/jfnetworker/` auf.
